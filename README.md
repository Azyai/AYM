# AYM - AI 面试助手

AYM 是一款免费的 Windows 桌面 AI 面试助手。通过悬浮面板提供实时语音问答、截图识题和基于个人经历的回答参考，可用于面试准备和模拟练习。

> 本说明适用于 **v0.6.1-astra**。

---

## 功能特性

### 语音实时问答

可选择系统音频、麦克风或两者同时输入。识别到的问题会交给模型生成流式答案。默认使用自动监听，按 `右 Ctrl + F` 暂停或恢复识别。

- **手动模式**下，按 `F5` 开始录音，再按一次停止并提交。
- **自动监听**会在说话停顿达到设定时间后提交问题。收音期间按 `F5` 可提前提交。
- **混合模式**平时自动监听。收音期间按 `F5` 提交当前问题，空闲时按 `F5` 开始手动录音。

自动监听的停顿等待默认 **2.5 秒**，可在设置中调至 **1–6 秒**，保存后立即生效。录音模式和停顿设置会在重启后保留。

### 截图识题

支持识别选择题、填空题、编程题和简答题。将鼠标分别移到截图区域的两个对角，用同一快捷键各按一次取点。

- **单图**用 `F1` 取点，截完立即发送。
- **多图**用 `F2` 逐张取点，最多缓存 **6 张**。完成选区后按 `F3`，按采集顺序发送整组截图。

软件同一时间处理一道题。语音正在收集时，可先按 `F5` 提交。当前回答结束后即可发起新的截图分析，也可按 `F4` 提前中断回答。截图进入发送流程后会清空该批待发送图片。

### 个人知识库（Wiki）

可上传项目、实习、工作经历的 Markdown 文档。遇到个人经历类问题时，AYM 会在本地检索相关章节和常见追问，依据你提供的材料生成回答。

- 同一公司的项目会归在同一段经历下，可在设置中拖拽调整公司和项目顺序。
- 点名项目时检索对应经历，宽泛的亮点与难点问题可汇总多个项目。
- 通用技术题直接交给模型回答，个人经历题结合 Wiki 资料回答。

### 面试场景与模型

支持技术面、综合面、HR 面和算法面。技术题会根据题目深度展开原理、技术对比和工程实践，较长的文字与截图回答有更高的输出上限。文本和截图可分别配置模型，个人技术栈和自定义热词可帮助识别专业术语。

### 悬浮窗口

悬浮面板支持鼠标穿透。页面大小可选默认、小窗或自定义。自定义尺寸会在重启后保留，实际显示会适配当前屏幕的可用区域。

窗口保护使用 Windows 的窗口捕获排除功能，效果取决于系统版本、共享软件及捕获方式。[Microsoft 窗口捕获文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)

### 局域网共享

开启共享后，同一局域网内的其他设备可以通过浏览器打开共享链接，实时查看问答。

### 历史记录与连续追问

用侧边栏或 `←` / `→` 翻题，用 `↑` / `↓` 滚动答案。翻阅旧题时停留在当前题，回到最后一题后恢复跟随。按 `F4` 中断回答时，已生成的内容会留在历史里，无答案的条目会自动移除。

语音问答和截图答题共用当前会话最近 **5 轮**有效问答。截图相关的语音追问可沿用会话中保留的图片。历史问答与图片在本次运行中保留。

## 快捷键一览

| 快捷键 | 功能 |
|---|---|
| `右 Ctrl + B` | 展开或收起回答面板 |
| `右 Ctrl + H` | 显示或隐藏整个窗口 |
| `右 Ctrl + F` | 暂停或恢复语音识别 |
| `F1` | 两次取点，发送一张截图 |
| `F2` | 两次取点，缓存一张截图 |
| `F3` | 批量发送已缓存的截图 |
| `F4` | 中断回答并保留已生成内容 |
| `F5` | 停止收音并提交，手动或混合模式下也可开始录音 |
| `← / →` | 上一题 / 下一题 |
| `↑ / ↓` | 答案向上 / 向下滚动 |

请使用键盘右侧的 `Ctrl` 触发组合键。单独按方向键在窗口隐藏时也会触发 AYM，`Win + 方向键` 等系统组合键保留原功能。需要退出时，在设置页底部点击 **退出软件**。

## 技术栈

| 层级 | 技术 |
|---|---|
| 桌面框架 | Tauri v2 |
| 前端 | React 19 + TypeScript + Vite |
| 后端 | Rust (Tokio 异步运行时) |
| 文本回答 | DeepSeek |
| 截图识别 | 通义千问 (DashScope) |
| 语音识别 | 豆包 (火山引擎) / 讯飞 |
| 音频捕获 | cpal (WASAPI Loopback) |
| 安装打包 | NSIS |

软件免费使用。模型和语音识别服务使用你配置的凭证，相关用量按对应服务商的规则计费。

## 使用说明

### 系统要求

- Windows 10 / 11 (x64)
- WebView2 Runtime（通常已预装）

### 安装

1. 下载 Windows x64 安装包（`.exe`）。[GitHub Releases](https://github.com/Azyai/AYM/releases)
2. 运行安装程序，按提示完成安装。
3. 启动需要管理员权限，请在 Windows 提示时授权。首次使用时输入激活码，可通过下方联系方式免费获取。

### 配置

启动后点击窗口右上角的设置按钮，进行以下配置：

1. 在 **模型与识别**中配置所选文本模型的 API Key。使用截图识题时配置截图模型，使用语音识别时配置豆包或讯飞凭证。
2. 在 **通用设置**的 **语音与回答**中选择回答场景、录音模式、音频来源和停顿等待时间。
3. 在 **个人资料**中按需填写技术栈、热词并上传 Wiki 文档。

本地开发时，请在已提升权限的终端中使用 `cargo run` 或 `tauri dev` 启动应用。编译和业务库测试可在普通权限下运行。

## 个人知识库文档格式

每个项目使用一个 `.md` 文件，同一家公司的多个项目分别上传。文件顶部的 `id` 与去掉 `.md` 后的文件名完全一致，`type` 按经历选择 `project`、`internship` 或 `work`。实习和工作项目的一级标题使用 `公司名称 — 项目名称`，便于按公司归组。

以下是 `project_ops_assistant.md` 的结构示例。文件从 `---` 开始，所有 Markdown 标题顶格书写。

```markdown
---
id: project_ops_assistant
type: project
aliases: [运维助手]
---

# 智能运维助手

## 基本信息
- 时间：{真实时间范围}
- 角色：{真实角色}
- 技术栈：{项目实际使用的技术，以 / 分隔}
- 类型：项目

## 项目概述
{简述项目解决的问题、本人职责和核心技术。}

## 职责与贡献
### {具体职责或模块名称}
- **本人动作**：{实际完成的工作}
- **可确认结果**：{可验证的结果}

## 核心技术实现
### {真实技术或机制}：{具体模块或目标}
{说明实际的调用链、数据流、算法或接口。}

## 亮点与难点
### 技术选型：{实际技术组合}
- **选型方案**：{当时采用的技术及选型理由}
- **决策来源**：{调研、官方文档等真实来源}

### 技术挑战：{实际问题与方案}
- **问题与约束**：{技术问题和限制}
- **解决方案与结果**：{所做改进及可确认的结果}

### 业务挑战：{实际业务问题}
- **服务人群**：{目标用户或业务方}
- **业务问题与影响**：{解决的问题及可确认的影响}

## 量化成果
- {填写有依据的指标，或注明“暂无可靠测量数据”}

## 如果现在优化
### {优化方向}
- **状态**：建议方案，尚未实施。
- **建议方案**：{可尝试的技术或方法}
- **适用条件与代价**：{说明引入成本}

## 高频追问 Q&A
### Q: {包含具体技术或模块名的完整问题}
A: {基于真实经历独立作答。}

## 关键词标签
[{真实技术}] [{真实机制}] [{真实模块}] [{业务领域}]
```

保留示例中的固定章节名。技术栈、关键词标签和三级标题使用项目实际采用的技术。后续设想写在「如果现在优化」的正文中，并标注实施状态。亮点与难点的某个维度缺少依据时，保留小节并填写「现有材料未说明」。

每个三级标题和每条问答应能独立理解，并至少准备一条亮点或挑战类问答。可在设置中点击 **复制 Wiki Skill 文档**，获取完整格式规范并交给 AI 辅助整理。
